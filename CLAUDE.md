@AGENTS.md

## Stack

Next.js 16 (App Router, Turbopack, `src/` dir, `@/*` → `src/*`), React 19, TypeScript, Tailwind CSS v4 (configured via `@tailwindcss/postcss` in `src/app/globals.css`, no `tailwind.config`), Better Auth, Drizzle ORM, Postgres on Neon. Package manager: npm.

## Commands

- `npm run dev` / `npm run build` / `npm run start`
- `npm run lint` — ESLint (flat config, `eslint.config.mjs`)
- `npx tsc --noEmit` — typecheck. `LayoutProps`/`PageProps` are global types generated by Next; run `npm run build` (or `npx next typegen`) first on a fresh checkout or tsc reports them missing.
- `npm run db:generate` / `db:migrate` / `db:push` / `db:studio` — drizzle-kit, reads `DATABASE_URL` from `.env.local`
- `npm run db:seed` — loads the sample catalog (`src/db/seed.ts`, via `tsx`)
- `npx auth generate --config src/lib/auth.ts --output src/db/auth-schema.ts --yes` — Better Auth CLI (the package's bin is `auth`, not `@better-auth/cli`); regenerates the auth tables after changing auth config or plugins, then run `db:generate`. `npx auth secret` generates `BETTER_AUTH_SECRET`.

- `npm run test` — Vitest (`vitest.config.mts`, node environment). Tests hit a real Postgres and run **only** against `TEST_DATABASE_URL` from `.env.test.local`: an empty Neon database whose name ends in `_test`. `tests/test-env.ts` refuses anything else and never reads `DATABASE_URL`/`.env.local`; global setup applies the committed `drizzle/` migrations to it. Never point tests at the store database or a branch of it.

## Architecture

- `src/db/index.ts` — single Drizzle client (`db`) over Neon's HTTP driver (`drizzle-orm/neon-http`). Throws at import if `DATABASE_URL` is unset, so anything importing `@/db` (including the auth route) needs it at build time too.
- `src/db/schema.ts` — all Drizzle tables; imported into the client as `schema` and referenced by `drizzle.config.ts`. Holds `categories`, `products`, `carts`, `cart_items`, `orders`, `order_items` and `payments`, and re-exports Better Auth's `user`, `session`, `account` and `verification` from the generated `src/db/auth-schema.ts` (don't hand-edit that file). Migrations `drizzle/0000`–`0006` cover all of them.
- `src/lib/auth.ts` — server-side Better Auth instance using `drizzleAdapter(db, { provider: "pg" })`. Refuses to load (so dev, build and start all fail) unless `BETTER_AUTH_SECRET` is 32+ random bytes as hex/base64 — don't relax this or fall back to Better Auth's default secret (`BETTER_AUTH_SECRETS` rotation is refused too). Email and password sign-in only, without email verification; the only plugin is `nextCookies()`, which must stay last. Logs through `src/lib/auth-logger.ts`, which prints the cause chain, redacts query params and escapes control characters. Server code gets sessions from `auth.api.*` via `src/lib/session.ts`.
- `src/lib/session.ts` — `getSession()` (cached per request), `requireSession(returnTo)` (redirects to `/sign-in?next=`) and `safeRedirect()`. Every protected page and Server Function calls `requireSession` itself; `src/proxy.ts` only checks for a session cookie (on `/account`, `/cart`, `/checkout`, `/orders`) to skip rendering for signed-out visitors. Redirect targets from user input go through `safeRedirect`.
- `src/app/(store)/(auth)/sign-in` and `sign-up` — pages around `AuthForm` (`src/components/auth/auth-form.tsx`, browser client). Errors shown to users go through `authErrorMessage` (`src/components/auth/auth-error.ts`), never Better Auth's own text.
- `src/app/api/auth/[...all]/route.ts` — mounts Better Auth via `toNextJsHandler(auth)`.
- `src/lib/products.ts` — product/category queries and the `Product`/`ProductSize`/`Category` types components use.
- `src/lib/catalog.ts` — static editorial content (hero, featured collections, campaign, services, nav) and display helpers (`formatPrice`, `stockState`/`stockLabel`, `categoryHref`, `unsplash()` image URLs, optionally with focal-point close-up crops).
- **Layouts:** `src/app/layout.tsx` is only `<html>`, `<body>`, font, `globals.css` and default metadata. Storefront routes live in the `(store)` route group (URLs unchanged), whose layout renders `StoreShell` (`src/components/store-shell.tsx`: cart count provider, header, `<main>`, footer). 404s: `src/app/(store)/not-found.tsx` handles `notFound()` in storefront pages (inside the store layout); `src/app/not-found.tsx` handles unmatched URLs and everything outside `(store)`, so it wraps itself in `StoreShell`. Both render `NotFoundMessage`. New storefront pages go under `src/app/(store)/`.
- `src/app/(store)/products/[slug]/page.tsx` — product detail page, prerendered from DB slugs; unknown slugs 404. Listings use the shared `ProductGrid` / `ProductCard` components.
- `src/lib/auth-client.ts` — browser client (`better-auth/react`), base URL from `NEXT_PUBLIC_BETTER_AUTH_URL`.

## Database conventions

- **Scope:** the catalog is only `categories` and `products`; carts are `carts` (one per user) and `cart_items` (one row per product + size), signed-in users only, with no price column. Deleting a product sets `cart_items.product_id` to null and keeps the row (with `product_name`) so the cart shows "No longer available" until the user removes it. Orders are `orders` (status enum `order_status`, new orders stay `pending_payment`; public `reference` like `SY-7K4Q9M2X` in URLs; delivery details copied on) and `order_items` (name, SKU, size and unit price copied at purchase). `orders.user_id` is `on delete restrict`. Payments are Paystack hosted checkout (test mode, `sk_test_` keys only): `payments` has one row per attempt (reference like `SY-7K4Q9M2X-P3F8Q2A9`); `orders.payment_reference` is the attempt that paid. Unpaid orders become `expired` after `PAYMENT_WINDOW_MINUTES` (60) and their stock returns; a `success` payment that isn't its order's `payment_reference` needs a manual refund. Don't add guest carts, discounts, reviews, wishlists or product variants unless asked.
- **Stock** is one integer column, `products.stock` (0 = sold out), not a separate table. `products.sizes` is display-only jsonb `{label, available}[]` (null = one size); it has no per-size quantities.
- **Money** is integer KES cents, kept to whole shillings (multiples of 100) because M-Pesa only takes whole shillings; `formatPrice` shows "KES 375,700". Order totals are `bigint`. `price` and `stock` have `>= 0` check constraints.
- **Keys:** primary keys are integer identity columns. Public identifiers are `slug` (unique, used in URLs) and `sku` (unique). Every product has exactly one category (`category_id` FK, `on delete restrict`).
- **Derived listings aren't categories.** "New In" / New Arrivals is ordered by `products.created_at`, not a category row.
- **Payments:** an order is marked paid only by `confirmPayment` (`src/lib/payments.ts`), after Paystack's verify API matches the reference, order id (metadata), amount and KES; never from the browser redirect. It's idempotent and shared by the webhook (`/api/webhooks/paystack`, HMAC-SHA512 signature), the callback page (`/orders/[reference]/payment`) and the expiry sweep (`expireUnpaidOrders`, run by `/api/cron/expire-orders` with `Authorization: Bearer $CRON_SECRET`, up to 100 orders, and after each checkout, up to 10). The sweep re-checks open attempts with Paystack and only expires an order once every open attempt of it was checked in that run; orders with an attempt younger than `PAYMENT_HOLD_MINUTES` (30) wait. An order may start at most `MAX_PAYMENT_ATTEMPTS` (10) attempts. Payments that don't match their order (`mismatch`) or can't be applied (`needs-refund`) are only logged so far. `src/lib/paystack.ts` is the HTTP client (15s timeout). Tests mock Paystack with `tests/paystack-mock.ts` and never reach the network.
- **Data access** goes through `src/lib/products.ts`, `src/lib/cart.ts`, `src/lib/stock.ts`, `src/lib/orders.ts` and `src/lib/payments.ts` only. Stock is only changed by the steps in `src/lib/stock.ts` (`decrementStock`, or `stockDecrementCtes` / `stockIncrementCtes` inside a larger statement): they lock the products in id order and update all or none. `placeOrder` (`src/lib/orders.ts`) is one statement that locks the ordered cart lines, takes the stock, creates the order and deletes those lines; it orders exactly the lines and quantities shown at checkout and is idempotent per checkout key. `reconcileCart` lowers saved quantities to available stock when the bag or checkout is viewed; sold-out lines stay in the bag and are left out of checkout. These are deliberately not `"use server"` exports, so callers must check the session first. Cart writes enforce stock (shared across a product's sizes) in the same SQL statement as the write; cart mutations are the Server Functions in `src/app/(store)/cart/actions.ts`. Pages and components don't import `@/db` directly, and client components use `import type` from it so the DB client isn't bundled. `src/lib/catalog.ts` holds static editorial content and display helpers only; product data doesn't go there.
- **Migrations:** edit `src/db/schema.ts`, run `npm run db:generate`, review the SQL in `drizzle/`, then run `npm run db:migrate`. Commit the `drizzle/` folder. Don't use `db:push` on shared or production databases.
- **Seed:** `src/db/seed.ts` must stay idempotent (upsert on `slug`). Update it whenever a schema change adds a required column.
- **Driver limits:** `neon-http` has no interactive transactions. Use `db.batch([...])` or idempotent sequential writes.
- **Freshness:** Cache Components is off. DB-backed pages set `export const revalidate = 60` (ISR) rather than being rebuilt for data changes.

## Design system

All tokens and primitives live in `src/app/globals.css` (Tailwind v4 CSS-first; no JS config). Monochrome, sharp corners (no radius), 1px hairlines, small uppercase tracked labels. Use the tokens (`text-ink`, `bg-surface`, `border-line`, `text-muted`, `px-gutter`, `h-header`, `text-sm`…) and composed utilities (`container-page`, `section`, `grid-products`, `media-frame`, `btn btn-primary|btn-secondary|btn-inverse`, `link`, `link-quiet`, `eyebrow`, `label`, `heading-*`) rather than raw palette colours or arbitrary values. Responsive spacing comes from CSS variables on `:root` (`--gutter`, `--section-y`, `--header-h`) that step up at 48rem and 80rem. The type scale overrides Tailwind's defaults (`text-base` is 14px). Light theme only.

## Environment

Copy `.env.example` to `.env.local`. `.gitignore` ignores `.env*` except `.env.example`. Variables: `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` (also the public base URL for Paystack callbacks), `NEXT_PUBLIC_BETTER_AUTH_URL`, `PAYSTACK_SECRET_KEY` (`sk_test_` only) and `CRON_SECRET`. Tests read `TEST_DATABASE_URL` from `.env.test.local` and set fake values for the rest.
